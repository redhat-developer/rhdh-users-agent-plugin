# RHDH 2.1 Release Notes

Red Hat Developer Hub 2.1 introduces a new Helm chart values structure. The chart name
(`redhat-developer-hub`) and Helm repo (`charts.openshift.io`) are unchanged, but the
values layout has been flattened from the nested `upstream.backstage.*` / `global.*`
structure used in 1.x.

Source: [upstream migration guide](https://github.com/redhat-developer/rhdh-chart/blob/release-2.1/charts/rhdh/docs/migration-from-backstage-chart.md)

## New features and enhancements

- **Flat values structure**: The chart owns all templates directly. Values previously nested under `upstream.backstage.*` are now at root level (e.g., `upstream.backstage.replicas` -> `replicaCount`).
- **StatefulSet workload kind**: Set `workload.kind: StatefulSet` for stable pod identity and persistent volumes via `volumeClaimTemplates`.
- **External database dedicated config**: `externalDatabase.*` block for configuring connection when `postgresql.enabled: false`.
- **OKP (Offline Knowledge Portal)**: `intelligentAssistant.okp.*` for offline RHDH documentation retrieval.
- **Intelligent Assistant rebranding**: Lightspeed rebranded to Intelligent Assistant (`intelligentAssistant.*`).
- **Default-deny NetworkPolicies**: Chart deploys default-deny policies allowing only DNS, PostgreSQL, and OpenShift ingress/monitoring traffic.
- **JSON Schema validation**: `values.schema.json` validates values at install/upgrade time.
- **Consistent global.imageRegistry**: Now documented and applied to all container images (useful for air-gapped environments).
- **Pre/extra init containers**: `preInitContainers` (before system) and `extraInitContainers` (after system) replace raw init container arrays.
- **Dynamic plugins volume config**: `dynamicPlugins.volume.*` replaces raw volume specs for plugin caching.
- **Per-image digest pinning**: Every image block (`image`, `catalogIndex.image`, `intelligentAssistant.core.image`, etc.) now has a `digest` field.

## Removed features (breaking changes)

- **`upstream.*` nesting removed**: All `upstream.backstage.*`, `upstream.service.*`, `upstream.serviceAccount.*`, `upstream.postgresql.*`, `upstream.metrics.*`, `upstream.httpRoute.*`, `upstream.ingress.*` paths replaced with root-level equivalents.
- **`global.clusterRouterBase`** moved to `openshift.clusterRouterBase`.
- **`global.host`** promoted to root `host`.
- **`global.dynamic.*`** moved to `dynamicPlugins.*`.
- **`global.auth.backend.*`** moved to `auth.backend.*`; `existingSecret` (string) becomes `existingSecretRef` (object with `name` and `key`).
- **`global.lightspeed.*`** replaced by `intelligentAssistant.*` with structural changes (image string splitting, configMap restructuring, secret handling changes, RAG init container removed).
- **`global.catalogIndex.*`** moved to `catalogIndex.*`.
- **`route.*`** moved to `openshift.route.*`.
- **`upstream.backstage.replicas`** renamed to `replicaCount`.
- **`upstream.backstage.annotations`** renamed to `deploymentAnnotations`.
- **`upstream.backstage.command`** renamed to `commandOverride`.
- **`upstream.backstage.args`** replaced by `extraArgs` (preferred, appends) or `argsOverride` (replaces all).
- **`upstream.backstage.extraEnvVars`** renamed to `extraEnv`.
- **`upstream.backstage.extraEnvVarsSecrets` / `extraEnvVarsCM`** merged into `extraEnvFrom` with structured `secretRef`/`configMapRef` entries.
- **`upstream.backstage.image.pullSecrets`** promoted to root `imagePullSecrets`.
- **`upstream.service.ports.backend`** flattened to `service.port`.
- **`upstream.service.nodePorts.backend`** flattened to `service.nodePort`.
- **`upstream.serviceAccount.automountServiceAccountToken`** renamed to `serviceAccount.automount`.
- **`upstream.backstage.pdb.*`** moved to `podDisruptionBudget.*`.
- **`upstream.backstage.autoscaling.maxReplicas`** default changed from 100 to 3.
- **`upstream.backstage.initContainers`** replaced by `dynamicPlugins.initContainer.*` for the dynamic-plugins init container; `preInitContainers`/`extraInitContainers` for custom ones.
- **`upstream.ingress`** restructured: single `host`/`path` becomes `hosts[]` array; `tls` becomes a list of structured entries.
- **`upstream.networkPolicy.*`** removed entirely; replaced by built-in default-deny policies.
- **`upstream.backstage.installDir`** removed (hardcoded).
- **`upstream.backstage.containerPorts.backend`** removed (hardcoded to 7007).
- **`upstream.diagnosticMode.*`** removed (not supported).
- **`test.injectTestNpmrcSecret`** removed.
- **Orchestrator flat fields** restructured: `externalDB*` fields nested under `externalDB.*`; image strings split into `image.*` objects; job fields nested under `dbCreationJob.*`.

## Known issues

- **PostgreSQL default version change**: Default image changed from PostgreSQL 15 to 18. Existing data directories require explicitly pinning `postgresql.image.tag` to the current version.
- **Leftover upstream keys pass silently**: The JSON Schema does not catch stale `upstream.*` keys. Run `helm template` to verify rendering before upgrading.
- **Intelligent Assistant secret**: The new chart does not create a placeholder secret. Customers must create the secret independently before upgrading.
- **HPA maxReplicas default**: Changed from 100 to 3; existing autoscaling configs may need adjustment.
- **Image digest/tag interaction**: The chart ships images with explicit digests by default. When both `tag` and `digest` are set, the chart renders `tag@digest`, which can fail to resolve at pull time if they don't match (the chart's default digest is merged by Helm). When overriding with a custom tag, either set `digest: ""` to clear the default, or set `digest` to the correct digest for your tag.
- **Air-gapped plugin references**: `global.imageRegistry` and `global.imagePullSecrets` apply to chart-managed container images only, not to dynamic plugin `oci://` or `ref://` references. Plugin images must be mirrored and referenced individually.

## Upgrade prerequisites

- Kubernetes 1.31+ / OpenShift 4.18+
- Migrate values file before upgrading (see `references/chart-migration-1x-2x.md`)
- Run `helm template` to validate the migrated values before applying
