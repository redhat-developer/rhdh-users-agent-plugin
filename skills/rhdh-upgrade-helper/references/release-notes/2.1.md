## Deprecated features

- **The generic fast OLM channel for the Red Hat Developer Hub Operator is deprecated**: The generic fast Operator Lifecycle Manager (OLM) channel for the Red Hat Developer Hub Operator is deprecated. New 2.y releases are published exclusively to versioned fast-X.Y channels, for example, fast-2.1.
- **The SIGUSR2 heap dump collection method is deprecated**: The SIGUSR2 heap dump collection method (--heap-dump-method=sigusr2) is deprecated and is planned for removal in a future release. The method still works in this release. To trigger and collect heap dumps from the Red Hat Developer Hub containers, use the default inspector method instead.
- **The signInPage configuration is deprecated**: The signInPage frontend configuration is deprecated. Because the sign-in page now automatically discovers and displays the authentication providers that you configure under auth.providers, a separate signInPage configuration is redundant. To control which providers appear on the sign-in page, configure them under auth.providers. For advanced customization, the dynamic plugin signInPage override remains available.
- **The Azure Container Registry plugin moves to Community support**: With this release, the Azure Container Registry (ACR) plugin (backstage-community-plugin-acr) moves from Technology Preview to the Community support level. To continue using this plugin, migrate to the oci:// reference in your configuration, for example
- **Material UI v4 is deprecated for plugins in favor of Backstage UI**: Red Hat recommends that plugin authors migrate plugins from Material UI (MUI) v4 to Backstage UI (BUI). Where an equivalent Backstage UI component is not available, use MUI v5 instead. Complete this migration before or during your next Red Hat Developer Hub upgrade to avoid UI regressions and unsupported dependencies.
- **Support level revised for some partner-owned plugins**: With this release, plugins that are developed by community partners are labeled with the Community support level instead of the Generally Available (GA) support level. This change differentiates Red Hat-owned plugins from plugins that are owned by other companies.
- **The disabled setting for dynamic plugins is deprecated**: The disabled setting in dynamic-plugins.yaml is deprecated but continues to work. The plugin loader logs a non-blocking warning for each plugin entry that uses it. Replace disabled: true with enabled: false, and disabled: false with enabled: true. The setting is scheduled for removal in Red Hat Developer Hub 2.3.
- **The Ping Identity plugin moves to the Community support level**: The @backstage-community/plugin-catalog-backend-module-pingidentity plugin moves from Technology Preview to the Community support level. For supported Ping Identity authentication, use the PingFederate plugin (@backstage-community/plugin-auth-backend-module-pingfederate-provider) instead.

## Removed features (breaking changes)

- **Scorecard provider configuration moves to scorecard.metricProviders**: This is a breaking change. Scorecard provider configuration moves from scorecard.plugins to scorecard.metricProviders in the app-config.yaml file. You must update your Scorecard configuration to use the new structure. You can configure thresholds in the application configuration for a provider (all metrics of the provider) or for individual metrics. Metric-level thresholds take precedence over provider-level thresholds. metricProviders.<datasource>.<providerName>.thresholds applies to all metrics that a provider provides. metricProviders.<datasource>.<providerName>.metrics.<metricName>.thresholds applies to one specific metric.
- **Scorecard aggregation cards must be reconfigured by using app.extensions in the New Frontend System**: This is a breaking change. In the New Frontend System, the previous Scorecard card mount points in dynamic-plugins.yaml no longer work. If you configured Scorecard aggregation cards through those mount points, you must reconfigure them by using app.extensions in app-config.yaml. In the New Frontend System, you configure Scorecard aggregation cards in the app-config.yaml application configuration file by using app.extensions.
- **TechDocs custom MkDocs plugins must be allowlisted**: With this release, TechDocs generation permits only a built-in set of MkDocs plugins, including techdocs-core, search, material/search, redirects, group, and material/group. Plugins outside that set are removed before the build, and a warning is logged. The MkDocs markdown_extensions configuration is also sanitized more strictly, including mapping-style declarations, so dangerous or dynamically configured entries might be stripped. Documentation that relied on custom MkDocs plugins builds without those plugins unless they are explicitly allowlisted. Features provided by removed plugins or stripped markdown extensions no longer appear in generated documentation.
- **The dynamic-home-page plugin is renamed to homepage**: Before this update, the home page plugin was named dynamic-home-page. With this release, the plugin is named homepage, and the dynamic-home-page name is no longer available. If your dynamic-plugins.yaml file references dynamic-home-page, update the entry to use homepage.
- **Default local database image updated to PostgreSQL 18**: This release changes the default image for the local (in-cluster) PostgreSQL database deployed by Red Hat Developer Hub from PostgreSQL 15 to PostgreSQL 18. PostgreSQL 15 remains supported, so you can continue to run the local database on PostgreSQL 15 if you prefer. PostgreSQL does not migrate data between major versions automatically. If you use the bundled local database and upgrade an existing deployment, the PostgreSQL 15 data directory is not compatible with the PostgreSQL 18 image, and the local database pod does not start until you migrate your data. Migrate your local database to PostgreSQL 18. Pin the local database image to a supported PostgreSQL 15 image.
- **Red Hat Developer Hub images are rebased on Red Hat Enterprise Linux 10**: This is a breaking change. The following feature-based permissions are available, each with the action set to use when enabled, instead of create, read, update, or delete: intelligent-assistant.chat intelligent-assistant.notebooks intelligent-assistant.mcp.tools intelligent-assistant.skills
- **The Plugin Certification Program is removed**: This release removes the Plugin Certification Program from Red Hat Developer Hub. Certification badges are removed from the Extensions Catalog metadata, and certification fields and labels are ignored. You no longer need to maintain the extensions.backstage.io/certified-by annotation.
- **Developer Lightspeed is renamed to the Red Hat Developer Hub intelligent assistant**: The AI assistant is renamed from Developer Lightspeed to the Red Hat Developer Hub intelligent assistant (formerly Developer Lightspeed for Developer Hub) to align with the Red Hat AI portfolio. This release focuses on the rename and includes user experience (UX), navigation, and configuration updates: This is a breaking change for existing deployments. Configuration keys and values in app-config.yaml that reference lightspeed are renamed to intelligent-assistant. You must update your configuration to use the new keys and values. User interface and visual updates: All user-facing text is updated. Legacy branded icons are replaced with official Red Hat AI design system tokens, including a…
- **Scorecard metric IDs use lowerCamelCase naming**: This is a breaking change that requires manual action. You must update your configuration to use lowerCamelCase for all Scorecard metric IDs to ensure compatibility. Before this update, Scorecard metric IDs followed the snake_case naming convention. With this update, the metric IDs are changed to lowerCamelCase to align them with the existing app-config.yaml naming convention.
- **app-config ConfigMaps must contain exactly one data entry**: This is a breaking change. Existing deployments that use multi-entry app-config ConfigMap resources break after this update. If you have a multi-entry app-config ConfigMap, split it into separate single-entry ConfigMap resources. All app-config ConfigMap resources, both the default and those specified in the custom resource (CR), must now contain exactly one data entry. This requirement ensures a predictable merge order, because Kubernetes does not guarantee the iteration order of ConfigMap data entries.
- **The Ping Identity catalog backend module plugin is removed**: The @backstage-community/plugin-catalog-backend-module-pingidentity plugin is removed from the Supported and Technology Preview catalogs and is no longer indexed. For supported Ping Identity authentication, use the PingFederate authentication provider (@backstage-community/plugin-auth-backend-module-pingfederate-provider). Community Open Container Initiative (OCI) images might still be available outside the curated catalogs.
- **The 1.10 RAG content image is no longer shipped**: The quay.io/rhdh/rhdh-rag-content-rhel9:1.10 image that the Lightspeed plugins used in 1.10 is no longer shipped. With this release, a new lightspeed-stack sidecar is used for the renamed intelligent assistant (formerly Developer Lightspeed) plugins.
- **OAuth sign-in no longer uses unverified emails**: With this release, OAuth profile handling respects negative email verification information from the identity provider. If the provider marks an email as unverified, Red Hat Developer Hub no longer uses that address for identity resolution. Users who previously signed in through an email-based OAuth sign-in resolver might fail to authenticate if their identity provider supplies an unverified email. Make sure that accounts used with Red Hat Developer Hub have verified emails at the provider, or use a sign-in resolver that does not depend on email.

## Known issues

- **Styles on other pages can render incorrectly after you visit Docs or a TechDocs entity tab** (RHDHBUGS-4055): After you open the Docs page or the TechDocs tab on a catalog entity, styles on other pages in Red Hat Developer Hub can render incorrectly until you reload the browser. Affected pages include Search, Settings, RBAC, catalog filters, login dialogs, theme switching, and other plugin pages. This issue occurs because TechDocs injects transformed styles into the page when the reader loads. A related fix is in progress in the upstream Backstage project. Workaround: After you leave Docs or the TechDocs tab, reload the browser page (hard refresh) to restore the correct styles.
- **Bulk import repository picker search does not match organization names** (RHDHBUGS-4017): In the bulk import flow, the search field on the repository picker matches only the repository name. It does not match the organization name or the full organization/repository path. If you have access to a large number of repositories and enter an organization name, the search returns no results. You cannot narrow the list to the repositories in that organization and must page through the full list to find your target. Workaround: Search for part of the repository name instead of the organization name. If you do not know the repository name, page through the repository list to find it.
- **Bulk import reports success when a pull request cannot be created** (RHDHBUGS-4016): When you run a bulk import that creates a pull request to add catalog-info.yaml files to your repositories, Red Hat Developer Hub can report the import as successful even if the pull request cannot be created. Red Hat Developer Hub also registers a catalog location for a catalog-info.yaml file that the pull request never added. The failure is recorded only as a warning in the backend log. The registered location then logs a warning on every catalog refresh cycle. Workaround: After the bulk import finishes, check that each imported repository received its pull request. For each repository without a pull request, remove the corresponding catalog location from the Catalog page. Retry the import for those repositories.
- **The Catalog page does not show the new empty state** (RHDHBUGS-3948): On entity-based pages, such as Catalog, APIs, Docs, and Self-service, the Catalog page does not show the new empty state. All other entity-based pages show the new empty state. For example, the Docs page shows the new empty state when no entity has a TechDocs annotation, or when you do not have access to any entity that has a TechDocs annotation.
- **The Backstage default not found page is shown instead of the Red Hat Developer Hub page** (RHDHBUGS-3947): When you navigate to a page that does not exist, or open a link to a page that you do not have permission to access, the Backstage default not found page is shown instead of the Red Hat Developer Hub not found page.
- **Duplicate plugin configurations can prevent Red Hat Developer Hub startup** (RHDHBUGS-3928): When the Intelligent Assistant or Orchestrator is enabled, adding plugins that are already provided by the feature can prevent Red Hat Developer Hub from starting, with a Duplicate OCI plugin configuration error. To work around this issue: For Helm installations, customize the existing entries under intelligentAssistant.plugins or orchestrator.plugins, and remove matching entries from dynamicPlugins.plugins. For Operator installations with OPERATOR_DP_PROCESSING=false, customize flavour-provided plugins by using their existing ref:// references instead of adding equivalent oci:// entries.
- **The Report an issue link is not visible on TechDocs pages in the New Frontend System** (RHDHBUGS-3664): In the New Frontend System, TechDocs add-ons use a different configuration, so the Report an issue link and other TechDocs add-ons are not visible. To work around this issue, enable the add-on in the app-config.yaml file
- **Possible slower response time in environments with a large number of plugins** (RHDHBUGS-4077): In environments with a large number of plugins, users might experience slower response time across the user interface and API operations, along with increased memory consumption. Core functionality remains unaffected, and performance optimizations are in progress to address these issues in an upcoming maintenance release.

## Fixed issues (upgrade-relevant)

- **The rhdh-cli plugin package command uses npm pack for staging** (RHDHBUGS-1968): Before this update, the rhdh-cli plugin package command performed a recursive copy of the contents of the dist-dynamic folder that is created by the rhdh-cli plugin export command. With this update, the command uses npm pack and extracts the result into its staging directory before it copies the exported plugin to its final destination or starts the container image build.
- **Improved accessibility of the Light theme** (RHDHBUGS-2243): Before this update, several UI elements did not meet Web Content Accessibility Guidelines (WCAG) 2.1 AA standards when the Red Hat Developer Hub Light theme was applied. The problems included buttons and toggle switches without accessible names, invalid ARIA attributes on tabs, list items with incorrect markup, interactive controls nested inside other controls in sortable table headers, and some text with insufficient color contrast. As a result, screen readers and other assistive technologies could not correctly read or use some parts of the interface. With this update, these problems are fixed in the Theme plugin. The Light theme now works better with assistive technologies and meets the required contrast ratios.
- **The OwnedEntityPicker field no longer fails with an HTTP 431 error** (RHDHBUGS-2522): Before this update, the OwnedEntityPicker field in software templates could fail with an HTTP 431 Request Header Fields Too Large error for users who belong to many groups with long names when multiple catalogFilter entries were configured. With this release, the picker correctly displays the entities that are owned by the user or their groups.
- **The Orchestrator database creation Job is renamed and fails correctly on errors** (RHDHBUGS-2577): The Orchestrator database creation Job is renamed from <release>-create-sonataflow-database to <release>-create-sf-db-<version>. When you upgrade, the old Job remains on the cluster and can be safely deleted manually. Before this update, the Job could silently succeed even when a database error occurred. With this release, the Job fails correctly on database errors and retries according to the backoffLimit setting (default: 2). backoffLimit activeDeadlineSeconds ttlSecondsAfterFinished
- **Scaffolder annotator action descriptions and examples are improved** (RHDHBUGS-2678): Before this update, the in-app self-documentation for the catalog:annotate, catalog:scaffolded-from, catalog:template:version, and catalog:timestamping actions in the Installed Actions catalog contained confusing descriptions and lacked code examples. With this update, the action descriptions are clarified to accurately state what each action does, and ready-to-use examples are added.
- **Catalog search visibility matches catalog browsing for HAS_LABEL and HAS_ANNOTATION policies** (RHDHBUGS-3011): Before this update, when catalog.entity.read was authorized with a conditional policy that used the built-in HAS_LABEL or HAS_ANNOTATION rule, entities could appear in the Software Catalog but be missing from catalog-backed search results, including TechDocs search. This happened when the label or annotation key in the entity YAML did not use the same casing as the name in the policy, for example, isPublic in the policy compared with ispublic in the YAML. The catalog list and query path normalized casing in its database filter, but the search authorization path evaluated the entity JSON with case-sensitive matching. With this update, the HAS_LABEL and HAS_ANNOTATION permission rules evaluate label and annotation keys and values case-insensitively, so catalog browsing and search visibility stay consistent for the same entity and policy.
- **Repository publishing actions no longer fail behind DPI proxies** (RHDHBUGS-3148): Before this update, the repository publishing actions (publish:github and github:repo:push) failed with an ECONNRESET error in enterprise environments that use Deep Packet Inspection (DPI) proxies. With this release, a fallback mechanism routes pushes through the GitHub GraphQL API over standard HTTPS JSON when binary Git smart protocol packets are rejected.
- **The AppBar no longer displays a box shadow** (RHDHBUGS-3181): Before this update, the AppBar component displayed a box shadow that was inconsistent with the Red Hat Developer Hub design. With this release, the box shadow is removed.
- **Hidden custom widgets no longer leave blank spaces in Orchestrator workflow forms** (RHDHBUGS-3186): Before this update, custom widgets in an Orchestrator workflow form that were marked with "ui:hidden": true, such as ActiveTextInput, ActiveMultiSelect, and SchemaUpdater, still rendered their container element, which produced large vertical blank spaces between visible fields. With this release, these hidden custom widgets are fully collapsed and no longer leave blank spaces.
- **Setting an empty flavours array now disables all default flavours** (RHDHBUGS-3198): Before this update, setting spec.flavours: (an empty array) in a Backstage custom resource (CR) did not disable the default flavours, and flavours with enabledByDefault: true were still loaded. With this update, setting spec.flavours: disables all default flavours, as documented. To use the default flavours, omit the spec.flavours field. The YAML syntax is unchanged.
- **GitHub SAML SSO token expiration no longer causes 403 error** (RHDHBUGS-3216): Before this update, when a GitHUB SAML SSO session expired, users would experience a 403 error despite having valid tokens. With this update, you can add a GitHub SAML SSO check step to your workflows. If the check detects a SAML SSO expiration, a re-authentication prompt appears.
- **Irrelevant wizard steps are hidden** (RHDHBUGS-3224): Before this update, wizard steps that did not apply were still shown. With this release, these steps are hidden when they are not relevant.
- **Filtering workflow runs by status and date works correctly** (RHDHBUGS-3225): Before this update, an error occurred when you filtered workflow runs by status and date. With this release, the workflow run list loads as expected when you use those filters.
- **Scorecard supports service account tokens for Jira Cloud** (RHDHBUGS-3322): Before this update, the Scorecard Jira provider supported only the default authentication method. Because Jira Cloud defaults to basic authentication, which is used for standard user tokens, you could not use service account tokens, which require bearer authentication. With this update, you can configure custom authentication types, so that service account tokens are fully supported.
- **Orchestrator workflow form validation errors clear as you enter a new value** (RHDHBUGS-3381): Before this update, field-level and top-level validation errors in an Orchestrator workflow form stayed visible after you entered a new value. With this release, these validation errors clear as you enter a new value.
- **Orchestrator Loki backend module no longer fails validation and crashes on boot** (RHDHBUGS-3397): Before this update, Orchestrator Loki backend module would fail validation and crash on boot if logPipelineFilters in app-config-yaml file contained brace characters { and } (standard LogQL text template syntax). This caused the local configuration validator to intercept the string value and reject the opening brace character. With this release, correctly formatted LogQL values are accepted by the validator.
- **Workflow run detail cards no longer overlap in content height mode** (RHDHBUGS-3429): Before this update, when the card height mode was set to content, the workflow run detail cards (Inputs and Results) could overlap, which caused overlapping text and broken layouts. With this release, the cards display correctly regardless of content size.
- **TechDocs page and table of contents scrollbars no longer overlap** (RHDHBUGS-3461): Before this update, when you viewed a TechDocs page, the document scrollbar and the table of contents scrollbar overlapped, which made the page difficult to use. With this release, scrolling occurs at the outer page level, and the scrollbar is positioned at the viewport edge so that it no longer conflicts with the table of contents scrollbar.
- **Dynamic plugin installation no longer delays pod termination** (RHDHBUGS-3463): Before this update, when the install-dynamic-plugins init container received a SIGTERM signal during a pod rolling update, eviction, or scale-down, child processes such as skopeo and npm were not terminated. These orphaned processes continued running until Kubernetes sent SIGKILL after the termination grace period, which caused pod shutdowns to take 30 to 139 seconds. With this release, the init container shell wrapper forwards SIGTERM to the entire process group, so that all child processes are terminated immediately. Pod shutdowns during dynamic plugin installation now complete in less than 5 seconds.
- **The RBAC interface performs better with large numbers of users and groups** (RHDHBUGS-3548): Before this update, the role-based access control (RBAC) interface became slow or unresponsive in environments with large numbers of users and groups. With this release, role page loading and member selection are improved, and the Edit button is no longer blocked while member data loads.
- **The intelligent assistant button no longer overlaps pagination controls** (RHDHBUGS-3563): Before this update, the intelligent assistant (formerly Developer Lightspeed) floating action button (FAB) overlapped the pagination controls, which made the Next button difficult to select. With this update, the floating action button is positioned above the pagination controls so that the Next button remains clickable.
- **The jira/custom-filter annotation value is validated** (RHDHBUGS-3646): Before this update, the value of the jira/custom-filter entity annotation was inserted into the Jira Query Language (JQL) query generated for the jira.openIssues metric without sufficient validation. A malformed or crafted value could therefore change the structure of the query rather than only narrowing which issues were counted, producing an incorrect issue count or a Jira query error. With this update, the annotation value is checked before the query is built. Parentheses and brackets must be balanced, string literals must be terminated, and a backslash is permitted only inside a string literal. Values that contain control characters, an ORDER BY clause, or a leading wildcard, or that are longer than 1,000 characters, are rejected. An invalid value now fails with an error that names the annotation and the reason, instead of being sent to Jira.
- **Disabled Scorecard metrics are no longer displayed from the database** (RHDHBUGS-3647): Before this update, disabling a metric, either globally in app-config.yaml or at the entity level by using annotations, stopped metric collection, but previously stored database values remained visible on the entity page, the homepage aggregated Scorecard cards, and the Scorecard Entities page. With this release, disabled metrics are hidden as follows: Globally disabled metrics: Hidden from the entity page, the homepage, and the Scorecard Entities page. Entity-level disabled metrics: Hidden from these surfaces only for the specific entities where they are disabled.
- **Toggling themes no longer remounts the application tree** (RHDHBUGS-3650): Before this update, toggling the theme triggered a full application tree remount, which caused unnecessary re-renders and lost local component state. With this release, toggling the theme no longer remounts the application tree, and local component state is preserved.
- **The Helm chart selects the correct PostgreSQL password secret key for custom usernames** (RHDHBUGS-3689): Before this update, the Red Hat Developer Hub Helm chart always used the postgres-password key, so a custom database username could not authenticate to the bundled PostgreSQL instance and the backend failed to start. With this release, the Helm chart selects the correct PostgreSQL password secret key when postgresql.auth.username is set to a value other than postgres.
- **Disabled metrics are hidden from Scorecard aggregated cards on the homepage** (RHDHBUGS-3917): Before this update, disabling a metric, either globally in app-config.yaml or at the entity level by using annotations, stopped metric collection, but previously stored database values remained visible on the homepage aggregated Scorecard cards and the Scorecard Entities page. With this release, disabled metrics are hidden as follows: Globally disabled metrics: Hidden from both the homepage and the Scorecard Entities page. Entity-level disabled metrics: Hidden from the aggregated Scorecard cards and the Scorecard Entities page, only for the specific entities where they are disabled.
- **Plugin builds now use up-to-date Adobe Spectrum, React Aria, and React Stately dependencies** (RHDHBUGS-3920): Before this update, the lockfile pinned the Adobe Spectrum, React Aria, and React Stately dependencies to outdated versions, so product builds of the plugins did not include the latest versions of these dependencies. With this release, the lockfile pinning is fixed, and the plugins are built with up-to-date Adobe Spectrum, React Aria, and React Stately dependencies.
